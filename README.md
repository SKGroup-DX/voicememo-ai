# ボイスメモ要約

iPhone純正「ボイスメモ」で録音・文字起こししたテキストを貼り付けると、AI（Gemini）が1on1／会議を自動で判定して要約し、ログイン名ごとに履歴として保存するアプリ（iOS向けPWA）。

アプリ：https://skgroup-dx.github.io/voicememo-ai/

## 構成

| 部分 | 中身 |
|---|---|
| 画面 | `index.html`（1ファイル。ReactをReact.createElementで直接書いている）、`sw.js`（オフライン用のキャッシュ）、`manifest.json`、アイコン。GitHub Pagesで公開 |
| サーバー | `gas/Code.gs`・`gas/appsscript.json`（Google Apps Script。スプレッドシートに紐づけてWebアプリとして公開） |
| 保存先 | スプレッドシートの `records` シート（1件1行、9列） |
| AI | Gemini API（無料枠）。APIキーではなく、スクリプト所有者のGoogleログイン権限で呼ぶ |
| テスト | `tests/`（GitHubにpushすると自動で実行される） |

### 流れ

1. ［要約する］を押すと、アプリは記録の番号（UUID）を決めて端末に「送信待ち」として保存し、すぐ入力欄を空にして「送っています…」を表示する（返事を待たせない）
2. 裏で「受け付け」（`submitTranscript`）と、本文付きの「要約開始」（`processRecord`）を同時に送る
3. GASは受け付けで文字起こしを保存する。要約開始は保存を待たずにすぐGeminiを呼び、終わったら同じ行に書き込む
4. その場で要約できなかった記録は、1分おきの定期実行（`runPendingJobs`）が要約する。受け付けたばかりの記録（押してから3分以内で、まだ誰も手を付けていないもの）は、要約開始と二重にならないよう定期実行は拾わない
5. アプリは「受け付けました。要約しています…」→「要約ができました」と表示を切り替える（要約開始の返事、または5秒おきの状況確認で）

- 送れなかったとき（電波がないなど）は「送信待ち」に残り、通信できるようになったら自動で送る（同じ番号で送るので2件にならない。日時は「要約する」を押したとき）
- AIには見出しの名前や絵文字を書かせず、短い名前（`goal` など）で項目だけを返させ、GASで保存する形に直す（書く量を減らして速くするため）
- 1on1／会議の判定が違うときは、要約画面の［会議として要約し直す］などで、種類を指定して要約し直せる（`resummarizeRecord`。新しい要約ができるまで前の要約は残る）
- 10分以上止まった処理は5分おきの `warmup` が要約待ちに戻す。同じ記録が3回止まったら失敗にする（［再試行］でやり直せる）

## records シートの列

| 列 | 見出し | 中身 |
|---|---|---|
| A | ID | 記録の番号（UUID） |
| B | 日時 | 受け付けた日時（送信待ちから送ったものは「要約する」を押した日時） |
| C | 名前 | ログイン名（空白は取り除いて保存） |
| D | 相手 | 相手・参加者（任意） |
| E | 状態 | `queued`（要約待ち）／`processing`（要約中）／`done`（完了）／`error`（失敗） |
| F | 要約 | 要約のJSON。要約し直しの間だけ `requestedType`（指定した種類）が入る |
| G | 文字起こし | 本文。保存期間を過ぎると空になる |
| H | エラー | 失敗したときの理由（利用者に見せてよい文言だけ） |
| I | 処理開始時刻 | 要約を始めた時刻（二重処理を防ぐ目印） |

先頭が `= + - @` の文字は、数式として扱われないよう `'` を付けて保存している（読むときに外す）。

## 秘密の情報について

このリポジトリは公開されています。合言葉やプロジェクトIDはコードに書かず、Apps Scriptの「プロジェクトの設定」→「スクリプト プロパティ」に保存します。

| プロパティ | 内容 |
|---|---|
| `APP_PASSCODE` | 社内共通の合言葉（必須。未設定だと誰も使えない）。12文字以上を推奨 |
| `GCP_PROJECT_ID` | Geminiの利用枠を付けるGoogle CloudのプロジェクトID（必須） |
| `GEMINI_MODEL` | 使うモデル（任意。未設定なら `gemini-3.5-flash-lite`） |
| `TRANSCRIPT_RETENTION_DAYS` | 文字起こしの本文を残す日数（任意。未設定なら90日、0なら消さない）。受け付けた日時から数え、過ぎた記録は要約だけ残る。変えたときは `index.html` の使い方の「90日」も直す |
| `GEMINI_THINKING_LEVEL` | AIが答える前に考える量（任意。`minimal`／`low`／`medium`／`high`。未設定なら `low`）。少ないほど速い。変える前に `testThinkingLevels` で速さと中身を比べる |
| `NO_THINKING_<モデル名>` | GASが自動で書く（そのモデルが考える量の指定を受け付けないことの記録）。消さない |
| `NO_FAST_CONFIG_<モデル名>` | GASが自動で書く（そのモデルがJSONの指定などの高速化の設定を受け付けないことの記録）。消さない |

### 気をつけること

- 履歴は「ログイン名」で分けているだけで、本人確認はしていない。合言葉を知っている人は、他の人の名前でログインすればその人の履歴を見られる（社内の限られた人数で使う前提）
- 無料枠のGeminiを使っているため、送った内容がGoogleのサービス改善に使われる場合がある（使い方の画面でも案内している）

## 初めて設定するとき

1. Googleスプレッドシートを新しく作り、「拡張機能」→「Apps Script」を開く
2. `gas/Code.gs` を「コード.gs」に、`gas/appsscript.json` を「appsscript.json」に貼り付けて保存する（appsscript.json は「プロジェクトの設定」→「「appsscript.json」マニフェスト ファイルをエディタで表示する」をオンにすると出る）
3. 「プロジェクトの設定」→「スクリプト プロパティ」に `APP_PASSCODE` と `GCP_PROJECT_ID` を入れる
4. Google Cloud のそのプロジェクトで「Generative Language API」を有効にする
5. エディタで `checkPasscodeSetting`、`testGeminiModel` を実行して確認する（初回は権限の許可を求められる）
6. エディタで `setupTriggers` を1回実行する（定期実行の作成）
7. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」で公開し、表示されたURLを `index.html` の `GAS_URL` に入れる

`records` シートは最初の受け付けのときに自動で作られる。

## GASの更新手順

1. `gas/Code.gs` の中身を、Apps Scriptエディタの「コード.gs」に全文貼り付けて保存する
2. 「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」→「デプロイ」（URLは変わらない）
3. デプロイ直後の1〜2分は、Google側で404になることがある（アプリは自動でやり直す）

定期実行を作り直すときは、エディタで `setupTriggers` を1回実行する（`runPendingJobs` 1分おき、`warmup` 5分おき、`purgeOldTranscripts` 毎日3時ごろ）。`purgeOldTranscripts` が無い場合は `warmup` が自動で作る。

### 合言葉を変えるとき

1. スクリプト プロパティの `APP_PASSCODE` を書き換えて保存する（再デプロイは不要）
2. 使っている人の画面は、次の通信で「合言葉が変わりました」と出てログイン画面に戻るので、新しい合言葉を伝える

### 確認用の関数（エディタから実行）

| 関数 | 用途 |
|---|---|
| `checkPasscodeSetting` | 合言葉が設定されているか（値は表示しない） |
| `testGeminiModel` | 今のモデルでGeminiを呼べるか |
| `listGeminiModels` | 使えるモデルの一覧（軽量版を先に表示） |
| `testThinkingLevels` | 考える量（`minimal`・`low`）ごとに例文を2回ずつ要約し、かかった時間と結果を表示する（AIを4回呼ぶ） |

### 計測シート

要約1件ごとに、経路（その場・本文付き・定期実行）、AIにかかった秒数、AIの呼び出し回数、混雑で待った秒数、押してから完了までの秒数などを、スプレッドシートの「計測」シートに残す（1分おきの定期実行がまとめて書く。シートは自動で作られる）。時間がかかった・ムラが出たときは、ここでどの段階が長いかを確かめる。

## 画面の更新手順

1. `index.html` などを変更する
2. **`sw.js` の `CACHE_NAME` の番号を1つ上げる**（例：`voicememo-ai-v11` → `v12`）。上げないと、ホーム画面に追加して使っている人に「新しいバージョンがあります［更新する］」が出ない
3. `main` にpushすると、GitHub Pagesに反映される

## テスト

```
node tests/run_all.js
```

| ファイル | 内容 |
|---|---|
| `tests/check_app.js` | `index.html` の中のすべてのスクリプトの構文チェック（1か所でも括弧が合わないと画面が真っ白になるため） |
| `tests/gas_core.test.js` | 受け付け・要約・やり直し・ロック・合言葉など、GASの基本の動き |
| `tests/gas_retention.test.js` | 要約の項目数、古い文字起こしの自動削除 |
| `tests/gas_features.test.js` | 種類を直して要約し直す、止まった処理の打ち切り、送信待ちの日時、自動削除の定期実行 |
| `tests/gas_speed.test.js` | 本文付きの要約開始、受け付け直後の待ち、AIの短い返答、考える量、計測 |

GASのテストは、本物の `gas/Code.gs` をスプレッドシートやGeminiの代わり（モック）の上で動かして確かめる。GitHubにpushすると、GitHub Actions（`.github/workflows/test.yml`）が自動で実行する。
